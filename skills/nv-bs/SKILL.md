# 브레인스토밍 스킬

## 시작 전 구조 확인

`docs/` 폴더가 존재하는지 확인한다. 없으면 아래 메시지를 출력하고 중단한다:

> "프로젝트 구조가 없습니다. `/init`을 먼저 실행해 주세요."

---

## 브레인스토밍 원칙

- **판단 유보**: 실현 가능성·완성도를 따지지 않고 일단 꺼낸다
- **양 우선**: 하나를 깊게 파기보다 여러 방향을 먼저 펼친다
- **연상 확장**: 나온 아이디어에서 "만약에", "반대라면", "더 극단적으로 가면"으로 가지를 뻗는다
- **연결 탐색**: 기존 인물·사건·세계관 요소와 연결될 지점을 찾는다

## 브레인스토밍 진행 방식

1. 요청 주제를 중심으로 아이디어를 자유롭게 나열한다
2. 유망한 방향에 "만약에" 질문을 던져 깊이를 더한다
3. 기존 `docs/characters/`, `docs/events/`, `docs/world/` 문서와 연결 가능한 지점을 확인한다
4. 아이디어를 타입별로 분류한다 (`character` / `setting` / `story` / `theme`)

## 결과물 저장

브레인스토밍이 마무리되면 `docs/idea/_template.md` 양식에 따라 해당 타입 폴더에 파일을 생성한다:
- `docs/idea/character/` — 인물·관계·캐릭터 아크
- `docs/idea/setting/` — 장소·시대·분위기
- `docs/idea/story/` — 플롯·씬·갈등 구조
- `docs/idea/theme/` — 주제·모티프·상징

**저장 기준**: 구체적인 설정·플롯 요소가 하나 이상 나왔으면 저장한다. 단순 질문·잡담 수준으로 끝난 경우는 저장하지 않는다. 판단이 애매하면 사용자에게 확인한다.

**복수 타입 아이디어**: 두 타입 이상에 걸치는 아이디어는 가장 핵심적인 타입 폴더에 저장하고, 파일 내 `연결 가능한 요소` 항목에 다른 타입과의 연결을 기록한다.

상태는 `구상 중`으로 시작하고, 아래 순서로 갱신한다:
`구상 중` → `검토 가능` → `반영 완료`

## 반영 결정

아이디어가 충분히 구체화되면 사용자에게 반영을 제안한다. 직접 이동하지 않고 반드시 확인을 받는다.

확인 후 아이디어 타입에 따라 목적지가 다르다:

| 타입 | 목적지 | 다음 단계 |
|------|--------|-----------|
| `character` | `docs/characters/{이름}.md` | `/wiki`로 설정 문서 작성 |
| `setting` | `docs/world/setting.md` 또는 `docs/world/rules.md` | `/wiki`로 설정 문서 작성 |
| `theme` | `docs/synopsis.md` 주요 테마 항목 | — |
| `story` (플롯·씬·사건) | `docs/TODO.md` | `/plan`으로 챕터 설계 |

반영 완료 시 원본 파일 상태를 `반영 완료`로 갱신한다.
