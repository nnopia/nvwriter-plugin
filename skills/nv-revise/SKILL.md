# 수정 스킬

검토 결과 또는 챕터 내 주석을 기반으로 이슈를 하나씩 처리합니다.

---

## 시작 전 구조 확인

`docs/`와 `src/` 폴더가 존재하는지 확인한다. 없으면 아래 메시지를 출력하고 중단한다:

> "프로젝트 구조가 없습니다. `/init`을 먼저 실행해 주세요."

---

## 이슈 수집

대상 챕터 파일에서 수정 주석을 수집한다.

**주석 형식** (CLAUDE.md `## 프로젝트 설정`의 `수정 주석 형식` 항목을 따른다):
- 설정이 없으면 기본값 `<!-- -->` 를 사용한다
- 리뷰 결과 주석: `<!-- [B] ... -->`, `<!-- [C] ... -->`
- 사용자 직접 작성 주석: 형식 자유 (기본 `<!-- ... -->`)

챕터가 지정되지 않으면 `src/TOC.md`를 읽어 `초고 완료` 상태인 챕터를 대상으로 한다.

**처리 순서**: `[C]` 주석 먼저, `[B]` 주석 나중. 같은 등급이면 파일 위에서 아래 순서로 처리한다.

---

## 수정 루프

수집된 이슈를 하나씩 처리한다. 모든 이슈가 처리될 때까지 반복한다.

### 각 이슈 처리 순서

**1단계 — 이슈 설명 및 참조 문서 확인**
- 이슈 내용을 요약한다
- 어느 챕터·씬·문장에 해당하는지 위치를 명시한다
- 이슈의 근본 원인을 분석한다
- 이슈 유형에 따라 관련 설정 문서를 열어 수정 기준으로 삼는다:
  - 인물 말투·성격·행동 관련 → 해당 인물의 `docs/characters/{이름}.md`
  - 장소·세계관·규칙 관련 → `docs/world/setting.md` 또는 `docs/world/rules.md`
  - 사건·인과관계 관련 → `docs/events/{사건명}.md`
  - 구조·씬 순서 관련 → `docs/plans/plan_ch{번호}.md`
  - 문체 관련 → `.claude/styles/default.md` (존재하는 경우)

**2단계 — 수정 방향 제안**
- 수정 방향을 2~3가지 제안한다
- 각 방향의 장단점을 간략히 설명한다
- 사용자가 제안 중 하나를 선택하거나 직접 다른 방향을 지시할 수 있다

**3단계 — 수정 실행**
- 확정된 방향으로 원고를 수정한다
- B 수준(문장·감정) 수정: 해당 부분을 직접 편집한다
- C 수준(구조·계획) 수정: `docs/plans/plan_ch{번호}.md` 재설계 후 원고를 재집필한다
  - 재집필 완료 후 nv-write 스킬의 집필 후 처리를 동일하게 수행한다 (설정 문서 갱신, TOC `초고 완료`, synopsis, overview 업데이트)

**4단계 — 이슈 해결 처리**
- 해당 주석을 챕터 파일에서 제거한다
- 수정 중 새 이슈가 발견되면: 해당 위치에 주석으로 추가하고 현재 루프가 끝난 뒤 처리한다

**5단계 — 다음 이슈로**
- 남은 이슈 수를 알려주고 다음 이슈로 넘어간다

---

## issues.md blocker 처리

수정 중 `[C]` 이슈가 `docs/issues.md`에 🔴 blocker로 등록된 경우:
- 해당 blocker를 먼저 해결한 뒤 챕터 수정을 진행한다
- blocker 해결 완료 시: `docs/issues.md`에서 해당 항목을 `- [x]` 체크하고 `## 해결 완료` 섹션으로 이동한다

---

## 전체 완료 후 처리

모든 주석이 제거되면:
1. 수정 내용 요약을 사용자에게 보고한다
2. `src/TOC.md` 상태를 `검토 완료`로 올려도 되는지 사용자에게 확인한다
3. 승인 시: `src/TOC.md` 상태를 `검토 완료`로 갱신하고 `docs/synopsis.md`를 업데이트한다. `docs/overview.md`의 파일별 요약에서 해당 챕터 상태를 갱신한다. 챕터에서 확정된 정보를 기존 설정 문서에 역방향 동기화한다 (CLAUDE.md `## 설정 동기화 원칙` 참조)
4. 미승인 시: 현재 상태(`초고 완료`)를 유지한다
